

# 🧠 Bit-Level Manipulation — Notes

*(With Read–Modify–Write (RMW) Problem Explained for STM32)*

---

## 🔹 What is a Bit?

A **bit** is the smallest unit of data in computing.
It can have only two states: **0 (LOW)** or **1 (HIGH)**.

Common bit operations in C:

```c
uint32_t reg = 0x00;     // All bits = 0
reg |=  (1U << 3);       // Set bit 3 (make it 1)
reg &= ~(1U << 3);       // Clear bit 3 (make it 0)
reg ^=  (1U << 3);       // Toggle bit 3 (flip 0→1 or 1→0)

if (reg & (1U << 3)) {   // Test bit 3
    // bit 3 is ON
}
```

---
🔹 What is a Mask?

A mask is a bit pattern used to select, isolate, or modify specific bits in a value using bitwise operations.

Example:

```c
uint8_t reg  = 0b11010110;
uint8_t mask = 0b00111100;
uint8_t result = reg & mask;   // Only the middle 4 bits remain
```

So, a mask helps you focus on specific bits while ignoring others.

---

## 🔹 What is a Field?

A **field** is a group of adjacent bits within a register that together represent a value.
For example, in STM32’s GPIO configuration register:

* Each pin uses 4 bits — **MODE[1:0]** and **CNF[1:0]**
* These bits together form a **field** controlling the pin’s behavior

Helper macro to generate a field mask:

```c
#define FIELD_MASK(width, pos) ((((1U) << (width)) - 1U) << (pos))
// Example: FIELD_MASK(4, 2) = 0b00000000000000000000000000111100
```

---

⚠️ The Read–Modify–Write (RMW) Problem

 🔸 What is it?

When the CPU changes one or more bits in a register, it usually does it in **three steps**:

1. **Read** → The CPU reads the entire 32-bit register value.
2. **Modify** → The CPU changes the bit(s) you wanted to set or clear.
3. **Write** → The CPU writes the modified value back to the register.

This sequence is called **Read–Modify–Write**.

---

### 🔸 Why is it a Problem?

If an **interrupt**, **DMA**, or **hardware event** modifies the same register **between** the read and write steps, that change may be lost.

This leads to incorrect or inconsistent register values — a **race condition**.

---

### 🔸 Example (GPIO ODR Register)

**Main code:**

```c
GPIOA->ODR |= (1U << 0);   // Set PA0
```

**Interrupt code:**

```c
GPIOA->ODR &= ~(1U << 1);  // Clear PA1
```

If the interrupt happens between the main code’s **read** and **write**,
PA1 might unintentionally turn ON again — because the main code overwrites the interrupt’s change.

---

## 🔹 Why RMW Happens

* MCU registers are 16-bit or 32-bit wide — the CPU must read/write the full register, even if you change only one bit.
* Many registers have **side effects** (e.g., flags that clear on read/write).
* The CPU does not automatically perform atomic (single-step) bit changes.

---

## 🔹 Consequences of RMW Problem

* Unintended GPIO behavior (e.g., LED turns on/off randomly)
* Missed interrupt flags or wrong status
* Data corruption when multiple agents (main, ISR, DMA) access the same register
* Difficult-to-debug, intermittent errors

---

## ✅ How to Prevent the RMW Problem

| Method                                       | Description                                                                                                              |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| **1. Use atomic registers (e.g., BSRR/BRR)** | STM32 provides special registers (like **BSRR**) for GPIO. Writing to them sets/resets bits atomically — no read needed. |
| **2. Disable interrupts briefly**            | Use `__disable_irq()` → modify → `__enable_irq()`. Prevents any interrupt during RMW sequence.                           |
| **3. Use Bit-Banding**                       | Cortex-M3 feature that allows atomic bit access via alias addresses. Each bit can be written directly.                   |
| **4. Use Shadow Registers**                  | Maintain a copy of the register in software, modify it safely, then write the full value.                                |
| **5. Use Mutex (in RTOS)**                   | In multitasking systems, use a mutex/lock to ensure only one task modifies the register at a time.                       |

---

## 🔹 STM32 Example — Safe vs Unsafe

```c
// ❌ Risky (causes RMW)
GPIOA->ODR |= (1U << 5);

// ✅ Safe (atomic)
GPIOA->BSRR = (1U << 5);           // Set PA5
GPIOA->BSRR = (1U << (16U + 5));   // Reset PA5
```

👉 `BSRR` is **write-only**. It sets or resets bits **in a single operation**,
so no read–modify–write happens — it’s **atomic** and **safe**.

---

## 🔹 Important Notes

* The `volatile` keyword stops compiler optimization but **does NOT prevent RMW problems**.
* Always prefer hardware atomic registers (like `BSRR`, `BRR`, or bit-banding).
* If you must disable interrupts, keep the disabled period **very short**.
* Be cautious with shared registers used by both **main** and **interrupt** code.

---

## 🔹 Handy Macros

```c
#define BIT(pos)       (1U << (pos))
#define SET_BIT(reg,b) ((reg) |=  (BIT(b)))
#define CLR_BIT(reg,b) ((reg) &= ~(BIT(b)))
#define TOG_BIT(reg,b) ((reg) ^=  (BIT(b)))
#define IS_SET(reg,b)  ((reg)  &  (BIT(b)))
```

## 🧩 Summary

| Concept         | Description                                                                        |
| --------------- | ---------------------------------------------------------------------------------- |
| **Bit**         | The smallest unit of data — 0 or 1                                                 |
| **Mask**        | A pattern used to isolate or modify specific bits                                  |
| **Field**       | A group of adjacent bits representing one setting/value                            |
| **RMW Problem** | Data loss when multiple agents modify a register between read and write            |
| **Fix**         | Use atomic hardware operations (`BSRR`, Bit-banding) or disable interrupts briefly |

---

### 🔸 In One Line:

> The **Read–Modify–Write Problem** occurs because the CPU reads and writes full registers, not bits.
> To avoid race conditions, use **atomic operations** (like BSRR) or **bit-banding** in Cortex-M3.
