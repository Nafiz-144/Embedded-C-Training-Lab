## Bit-level Manipulation — Notes

This note explains basic bit concepts, masks, fields, and the Read–Modify–Write (RMW) problem with practical C examples and STM32-specific fixes.

### What is a bit?

A bit is the smallest unit of data in computing. It can be 0 or 1.

Common bit operations in C (assuming an unsigned integer register):

```c
uint32_t reg = 0x00;       // all bits = 0
reg |=  (1U << 3);         // set bit 3 to 1
reg &= ~(1U << 3);         // clear bit 3 to 0
reg ^=  (1U << 3);         // toggle bit 3

if (reg & (1U << 3)) {    // test bit 3
    // bit 3 is set
}
```

### What is a mask?

A mask is a bit pattern used to select or isolate specific bits from a value using bitwise operators.

Example:

```c
uint8_t reg  = 0b11010110;
uint8_t mask = 0b00111100;
uint8_t result = reg & mask; // result contains only the middle 4 bits (masked)
```

### What is a field?

A field is a group of adjacent bits within a register that together represent a value (for example MODE[1:0] in GPIO configuration).

Many MCU peripheral registers pack multiple fields into a single 16/32-bit register. Use masks and shifts to read or write fields.

Helper macro to create a field mask:

```c
#define FIELD_MASK(width, pos) ((((1U) << (width)) - 1U) << (pos))
// Example: FIELD_MASK(4, 2) => 0b0000_0000_0000_0000_0000_0000_0011_1100
```

## Read–Modify–Write (RMW) Problem

When code changes bits in a hardware register, it often performs three steps:
1. Read the full register value.
2. Modify the desired bits in software.
3. Write the full register value back.

If an interrupt, DMA, or another agent modifies that register between the read and the write, those external changes can be lost when the original writer performs the final write. This is the RMW problem (a race condition).

### Simple example (GPIO ODR)

Main code:

```c
GPIOA->ODR |= (1U << 0);   // set PA0
```

Interrupt code:

```c
GPIOA->ODR &= ~(1U << 1);  // clear PA1
```

If the interrupt runs between the read and write of the main code, the interrupt's change may be overwritten and lost.

### Why RMW happens

- Registers are read/written as whole words (16/32 bits), but you may change only a single bit.
- The CPU cannot atomically change a single bit unless the hardware provides a mechanism.
- Some registers have side effects on read/write, making RMW risky.

### Consequences

- Wrong peripheral state (e.g., unintended GPIO output)
- Lost updates to flags or control bits
- Intermittent, hard-to-debug bugs

## Ways to avoid the RMW problem

1. Use hardware atomic registers where available (STM32 example: BSRR/BRR for GPIOs).
2. Disable interrupts for very short critical sections: __disable_irq(); modify; __enable_irq();
3. Use Cortex-M bit-banding (where supported) to write single bits atomically.
4. Use an RTOS mutex or other synchronization for multitasking systems.
5. Maintain a software 'shadow' copy and carefully synchronize updates when appropriate.

### STM32-specific: BSRR example (atomic GPIO set/reset)

```c
// Risky (may cause RMW):
GPIOA->ODR |= (1U << 5);

// Safe (atomic):
GPIOA->BSRR = (1U << 5);           // set bit 5
GPIOA->BSRR = (1U << (16U + 5));   // reset bit 5
```

`BSRR` is a write-only register that sets or resets bits atomically — no read-modify-write is performed.

## Important notes

- The `volatile` keyword prevents compiler optimizations but does NOT solve RMW concurrency issues.
- Prefer hardware atomic operations when available.
- Keep critical sections as short as possible if you disable interrupts.

## Quick reference macros

```c
#define BIT(pos)       (1U << (pos))
#define SET_BIT(reg,b) ((reg) |= (BIT(b)))
#define CLR_BIT(reg,b) ((reg) &= ~(BIT(b)))
#define TOG_BIT(reg,b) ((reg) ^= (BIT(b)))
#define IS_SET(reg,b)  ((reg) & (BIT(b)))
```

## Summary

Bit-level manipulation is fundamental in embedded C. Understand masks, fields, and the RMW problem. When working with shared hardware registers, prefer atomic hardware mechanisms (like BSRR on STM32), or protect access with very short critical sections or synchronization primitives.

What is Read-Modify-write Problem


A **Read–Modify–Write (RMW)** operation happens when the microcontroller changes a specific bit or field in a register by performing three steps internally:

1. **Read** → The CPU reads the entire register value.
2. **Modify** → It changes (sets or clears) specific bits as required by the code.
3. **Write** → It writes back the modified value to the same register.

All three steps occur as one logical operation — **Read → Modify → Write**.

---

## Why is it a Problem?

If an **interrupt**, **DMA**, or **hardware event** occurs between the Read and Write phases,
then the register value might change unexpectedly.

When the CPU writes back its modified value, it overwrites the new changes made by the interrupt or hardware.
As a result, those updates are **lost** — this is called the **RMW problem** or **race condition**.

---

## Example

Assume `GPIOA->ODR` controls the output pins.

### Main code:

```c
GPIOA->ODR |= (1 << 0);   // Set PA0 high
```

### Interrupt code:

```c
GPIOA->ODR &= ~(1 << 1);  // Clear PA1
```

If the interrupt runs between the Read and Write of the main code,
the interrupt’s change (clearing PA1) can be lost.
The main code writes an older value back into the register, restoring PA1 to 1.

---

## Why RMW Happens in Microcontrollers

* Registers are word-sized (16-bit, 32-bit, etc.), but you often modify only one bit.
* The CPU can only read/write the **entire register**, not a single bit.
* Many peripheral registers have **side effects** when read or written (e.g., auto-clear flags).

---

## Consequences of RMW Problem

* Wrong or unexpected output (e.g., LED turns on/off incorrectly)
* Interrupt flags not cleared properly
* Data corruption in shared registers
* Hard-to-debug intermittent errors

---

## Ways to Prevent the RMW Problem

| Method                                        | Description                                                                                                                  |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **1. Use atomic registers (e.g., BSRR, BRR)** | In STM32, the `BSRR` (Bit Set/Reset Register) allows you to set or reset specific bits in one atomic write without any read. |
| **2. Disable interrupts temporarily**         | Use `__disable_irq()` before the operation and `__enable_irq()` afterward to prevent interruptions during RMW.               |
| **3. Use bit-banding (Cortex-M feature)**     | Access a single bit through its bit-band alias address — makes it atomic.                                                    |
| **4. Use shadow register in software**        | Keep a copy of the register value in a variable, modify it, and then write back the full value safely.                       |
| **5. Use RTOS mutex or lock**                 | In multitasking environments, use synchronization primitives to prevent concurrent access.                                   |

---

## Safe Method in STM32 (Example)

```c
// ❌ Risky (RMW problem possible)
GPIOA->ODR |= (1 << 5);

// ✅ Safe (Atomic operation)
GPIOA->BSRR = (1 << 5);           // Set bit 5
GPIOA->BSRR = (1 << (16 + 5));    // Reset bit 5
```

`BSRR` is a **write-only register**, so there is no read operation — making it atomic and RMW-safe.

---

## Important Points

* RMW occurs because the CPU reads and writes the entire register even when only one bit changes.
* Interrupts or concurrent access can cause race conditions.
* Use atomic operations or hardware-specific atomic registers (like BSRR).
* `volatile` keyword prevents compiler optimization but does **not** solve RMW issues.
* In STM32, always prefer **BSRR** or **BRR** for GPIO control instead of ODR.

---

## Summary

> The **Read–Modify–Write Problem** occurs when two or more operations (main code, interrupt, DMA, etc.) access and modify the same register concurrently.
> Because the CPU performs read–modify–write in three separate steps, one operation can overwrite another’s change.
>
> The solution is to use atomic operations (like BSRR), disable interrupts temporarily, or use hardware/RTOS mechanisms that ensure exclusive access.
