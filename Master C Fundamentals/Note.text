
# Master C Fundamentals — Simple Notes (for Embedded Systems)


## 1. What is `<stdint.h>`?

`<stdint.h>` is a header file in C that defines integer data types with **fixed size**.

It helps to make sure your variables always use the same number of bits on any microcontroller or computer.

Examples of fixed-width types:

* `uint8_t` → unsigned 8-bit integer (0 to 255)
* `int16_t` → signed 16-bit integer (-32768 to 32767)
* `uint32_t` → unsigned 32-bit integer (0 to 4,294,967,295)

Example:

```c
#include <stdint.h>

uint8_t led_state;     // 8-bit
int16_t temperature;   // 16-bit
uint32_t sensor_data;  // 32-bit
```

Why use it?

* For microcontrollers, register size is fixed (like 8, 16, or 32 bits).
* Using `<stdint.h>` makes your program work correctly on all platforms.

Real-life example:
When accessing a 32-bit STM32 register:

```c
#define GPIOA_ODR (*(volatile uint32_t*)0x4001080C)
```

Here `uint32_t` is used because the register is 32 bits wide.

## 2. What is `volatile`?

The `volatile` keyword tells the compiler:
“Do not optimize this variable — its value can change at any time.”

Why?
Because in embedded systems, some variables are changed by **hardware** or **interrupts**, not by normal program code.

Example:

```c
volatile int flag = 0;

void Timer_ISR(void) {
    flag = 1;  // interrupt sets flag
}

int main(void) {
    while (!flag) {
        // waiting for interrupt
    }
    // continue program
}
```

If you don’t use `volatile`, the compiler may think `flag` never changes and skip checking it again — causing an infinite loop.

Common uses:

* For hardware registers
* For global flags shared with interrupts
* For variables that can change outside normal code

Example in STM32:

```c
volatile uint8_t button_pressed = 0;

void EXTI0_IRQHandler(void) {
    button_pressed = 1;
}
```

Remember:

* `volatile` does NOT make variable access safe between threads or cores.
* It only prevents compiler optimization.

## 3. What is `const`?

`const` means the variable cannot be changed after initialization.
It’s read-only.

Example:

```c
const float PI = 3.1416;
```

If you try to change PI later, the compiler will show an error.

Why use `const`?

* To protect important data from accidental change.
* To store constant data in Flash memory instead of RAM (in microcontrollers).

Pointer examples:

```c
int x = 10;
const int *p1 = &x;  // cannot modify value through p1
int * const p2 = &x; // p2 always points to same address
```

Real-life example:
A lookup table used in ADC calibration:

```c
const uint16_t table[] = {100, 200, 400, 800, 1600};
```

## 4. What is a `struct`?

A `struct` (structure) is a way to group different types of variables under one name.

Each member of a struct has its own separate memory.

Example:

```c
struct Sensor {
    uint8_t id;
    float temperature;
    float humidity;
};

struct Sensor sensor1;
sensor1.id = 1;
sensor1.temperature = 25.5;
sensor1.humidity = 60.2;
```

Real-life example:

```c
struct GPS_Data {
    float latitude;
    float longitude;
    float altitude;
};
```

Here you can store all GPS data together inside one structure.

## 5. What is a `union`?

A `union` also groups variables, but all members share the **same memory location**.
That means, only one member holds a valid value at a time.

Example:

```c
union Data {
    int i;
    float f;
    char str[20];
};

union Data data;
data.i = 100;
```

Now the same memory that stores `i` can also be used to store `f` or `str`.

Why use union?

* To save memory.
* To access the same data in different forms (e.g., bytes vs integer).

Example:

```c
union {
    uint32_t all;
    uint8_t bytes[4];
} sensor_data;

sensor_data.all = 0x12345678;
```

Now you can read each byte separately using `sensor_data.bytes[0..3]`.

## 6. Difference between `struct` and `union`

| Feature  | Struct                         | Union                            |
| -------- | ------------------------------ | -------------------------------- |
| Memory   | Each member has its own memory | All members share same memory    |
| Size     | Sum of all members + padding   | Size of largest member           |
| Use case | Store multiple values at once  | Reuse memory for different views |
| Example  | Sensor data                    | Data conversion (bytes ↔ int)    |

Example of padding in `struct`:

```c
struct Example {
    uint8_t a;
    uint32_t b;
    uint8_t c;
};
```

Size may be 12 bytes due to padding.
Compiler aligns data to make memory access faster.

## 7. What is `enum`?

`enum` (Enumeration) is a user-defined data type that gives names to integer constants.

It makes code easier to read and understand.

Example:

```c
enum SystemState {
    IDLE,
    RUNNING,
    ERROR
};
```

Here:

* IDLE = 0
* RUNNING = 1
* ERROR = 2

Example program:

```c
#include <stdio.h>

enum SystemState { IDLE, RUNNING, ERROR };

int main(void) {
    enum SystemState state = RUNNING;

    if (state == IDLE) {
        printf("System is Idle.\n");
    }
    else if (state == RUNNING) {
        printf("System is Running.\n");
    }
    else if (state == ERROR) {
        printf("System has Error!\n");
    }
}
```

Output:

```
System is Running.
```

You can also assign custom values:

```c
enum Level {
    LOW = 10,
    MEDIUM = 20,
    HIGH = 30
};
```

You can mix values too:

```c
enum Example {
    A = 5,
    B,     // 6
    C = 10,
    D      // 11
};
```

### Real-life example (State Machine in Embedded System)

Enums are very useful to describe system states in embedded code.

Example:

```c
enum SystemState {
    INIT,
    SENSING,
    ALERT
};

int main(void) {
    enum SystemState state = INIT;

    while (1) {
        switch (state) {
            case INIT:
                // Initialize sensors
                state = SENSING;
                break;

            case SENSING:
                // Read sensors
                if (/* condition */ 1) {
                    state = ALERT;
                }
                break;

            case ALERT:
                // Turn on buzzer
                state = SENSING;
                break;
        }
    }
}
```

Enums make your state machine clear and easy to modify later.

## 8. Common mistakes (and how to avoid them)

1. Using `volatile` for thread safety
   → Wrong. It only prevents compiler optimization, not atomic access.

2. Ignoring struct padding
   → Be careful when sending struct data through serial or network.
   Use `#pragma pack(1)` only if you understand alignment issues.

3. Using `union` for type conversion
   → It may not be portable. Better to use `memcpy` for safe data copy.

4. Misunderstanding `const` pointer
   → `const int *p` means you cannot change the value,
   but `int * const p` means you cannot change the pointer address.

5. Forgetting to initialize `enum` variables
   → Always set an initial state like `enum SystemState state = INIT;`

## 10. Key Takeaways

* `<stdint.h>` → ensures fixed-size integers.
* `volatile` → tells compiler not to optimize variable access.
* `const` → makes variables read-only.
* `struct` → groups related variables together.
* `union` → lets multiple variables share the same memory.
* `enum` → gives names to numbers (useful for modes, states, and errors).
* All these are heavily used in embedded system programming.
